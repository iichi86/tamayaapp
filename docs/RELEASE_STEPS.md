| 段階 | 開発側・用意する自動処理 | 所有者に必要な操作 | 完了の目印 |

| 3．画像内容は確認済み：Appleへの登録を進める | 受領した3画面の内容を確認。サイズエラー用にWindowsで1179×2556のコピーを作る処理を用意 | サイズ調整ツールで画像3枚を選択し、生成されたPNGをAppleへ追加。チャットへの送り直しは不要 | Appleに画像が登録され、正しく表示される |

この作業環境から所有者のPCやApple管理画面を直接操作する接続はありません。そのため、ログイン・認証コード・本人固有の情報の入力と、実機操作は所有者の端末で行います。ファイル作成・修正・検証・実行手順の作成は開発側で進めます。秘密鍵やパスワードをチャットへ送る必要はありません。

## 今は掲載画像と審査情報を準備する

ホーム・お店・会員証下部の条件の3画面は受領し、内容を確認済みです。[掲載画像](APP_STORE_SCREENSHOTS.md)の寸法と登録は、Appleへの画像追加時に確認します。[非公開の審査情報](RELEASE_METADATA.md)は、所有者のPCで掲載文・連絡先・著作権・専用一般会員のログイン設定まで準備完了しました。入力・ファイル選択を繰り返す必要はありません。[掲載文・審査情報の同期](RELEASE_METADATA.md#11月6日掲載情報の同期が成功)は成功表示を確認しました。次は[Appleの掲載画面](https://appstoreconnect.apple.com/apps/6830628549/appstore)で画像登録と残る必須項目を整えます。普段のオーナーアカウントのログイン情報を審査へ提供する必要はありません。

### TestFlight導入時の参照

1. PCで[今回のTestFlight画面](https://appstoreconnect.apple.com/apps/6830628549/testflight/ios)を開きます。
2. バージョン`1.0.0`・ビルド`2`の処理状況を確認します。処理中の場合はApple側の完了を待ちます。処理時間に固定の期限は設けません。
3. 処理が終わったら、iPhoneへAppleの[TestFlight](https://apps.apple.com/jp/app/testflight/id899247664)を入れ、登録されたテスターとして玉屋のアプリをインストールします。今回は内部グループ`Team (Expo)`への参加・インストール完了の報告を受けています。
4. TestFlight版が開いたら、起動・ログイン・会員情報・QR等の必要な確認と、掲載画像の撮影へ進みます。

ビルドとアップロードは成功済みです。処理待ちを解消するために、同じビルドや提出を作り直す手順には進みません。App Reviewへの審査提出・一般公開は、この後の実機と掲載情報の準備を終えた段階です。

## 完了した段階1・2の一括操作（参照用）

以下は今回実行した操作の記録です。再実行は不要です。

Windowsキーを押しながらRを押し、`cmd`と入力してEnterを押します。黒い画面で次の1行を実行します。

```bat
cd /d "%USERPROFILE%\Downloads\tamaya-server-setup\tamayaapp-main" && curl.exe -fL --retry 3 "https://raw.githubusercontent.com/iichi86/tamayaapp/e81bd799185aa00585cedab95a198d0646e4ee6f/scripts/prepare-ios-build.mjs" -o "scripts\prepare-ios-build.mjs" && node scripts\prepare-ios-build.mjs --build --submit
```

このコマンドは、用意した準備スクリプトを取得して実行します。スクリプトの内部では検証済みコミットのファイルを取得し、内容のハッシュが一致してから更新します。既存の接続設定を保持し、今回承認された設定を更新して、チェックとビルドへ進みます。ビルド成功後はTestFlightへのアップロードも自動で進めます。ダウンロードや確認に失敗した場合はエラーを表示して止まります。

Appleのログイン・認証コード・アップロード用の鍵等を求められたら、ご本人が黒い画面で対応します。質問の意味が分からない場合は、その画面を送ってください。ビルドが始まった場合は、表示されたExpoのビルド画面で状況を確認します。ビルド・アップロードの結果を確認してから、iPhoneへTestFlight版を入れる操作を案内します。

この一括操作は、段階1のビルドと段階2のアップロードを対象にします。App Reviewへの審査提出と一般公開は、実機・掲載情報の準備を終えた後の段階です。`--submit`を省いた`--build`のみの指定ではビルドまで、`--local-only`ではローカルの更新・チェックまでを実行できます。

EAS CLI 25.3.0の提出処理には、必要なApp Store Connectのアプリ登録と内部TestFlightグループの準備を進める機能があります。今回の`eas.json`には掲載名「むさしの玉屋」、日本語`ja`、SKU、正式なBundle IDを設定しました。最初から同じ情報をブラウザーへ手入力する手順を標準にはしません。

今回の一括操作で、App Store Connectの準備とアップロードは成功済みです。下記の提出操作は、将来改めて提出が必要になった場合の参照用です。再提出する場合は対象を確認します。対象が明確な場合は`--id`を指定し、今回のプロジェクトに対象の最新ビルドだけがある場合は次の操作を使えます。


これはAppleへのアプリ本体のアップロードです。一般公開の審査提出・公開ボタンとは別の段階です。Appleから契約の確認が求められた場合や、名称が使用できない場合は、表示内容に合わせて対応します。自動作成後の掲載名が「むさしの玉屋」であることも確認します。
