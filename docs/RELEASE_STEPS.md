# 公開までの進め方

更新日：2026年11月4日（日本時間）。所有者から「公開まで段階的に進め、手作業は最小限にする」との依頼を受け、署名付きビルド、TestFlight、ストア掲載、審査、一般公開までを対象にします。

現在は、アプリ本体、正式な規約・プライバシー、店舗のロゴ、AppleのBundle ID、EASの接続設定を用意した段階です。所有者のPCへの最新ファイル・承認設定の反映、署名付きビルド、TestFlight送信、App Store公開はまだ確認していません。済んだ操作を一からやり直す必要はありません。

## 段階と役割

| 段階 | 開発側・用意する自動処理 | 所有者に必要な操作 | 完了の目印 |
| --- | --- | --- | --- |
| 1．iPhone用アプリを作る | 最新の6ファイル取得・検証、必要な設定更新、公開サーバーの確認、配布前チェック、EASビルド開始 | 準備コマンドの実行。Appleログイン・2段階認証・証明書作成等の質問への回答 | ExpoでiOSビルドが成功 |
| 2．TestFlightへ入れる | ビルド成功後の自動アップロード、App Store Connectのアプリ登録・内部テスト設定。名前、日本語、識別子等は設定済み | 必要な認証と、アップロード用の鍵等の確認。iPhoneへのインストール | TestFlightにビルドが表示され、iPhoneへインストールできる |
| 3．実機と掲載画像を確認する | 署名版で確認する要点を絞り、不具合の修正と撮影画像の整理を進める | TestFlight版を開き、指定した要点を確認。実際の画面を撮影して送る | 実機の基本動作と掲載画像がそろう |
| 4．ストアの掲載情報を入れる | 日本語の掲載文・URL等をファイル化して同期。プライバシー申告と審査メモを準備 | 本人の審査連絡先や権利情報をPC・Appleの画面へ入力し、必要な回答を選択 | 必須項目が埋まり、提出できる状態 |
| 5．Appleの審査へ出す | 審査提出に必要な確認、Appleの指摘の分析と修正。公開時のサーバー・バックアップ運用も整理 | 現在の管理アクセスでは、ご本人の画面で提出操作とAppleからの連絡確認 | App Reviewで承認 |
| 6．一般公開する | 公開前後の接続・表示の確認と問題の修正 | 現在の管理アクセスでは、管理画面の公開操作 | App Storeからインストールできる |

この作業環境から所有者のPCやApple管理画面を直接操作する接続はありません。そのため、ログイン・認証コード・本人固有の情報の入力と、実機操作は所有者の端末で行います。ファイル作成・修正・検証・実行手順の作成は開発側で進めます。秘密鍵やパスワードをチャットへ送る必要はありません。

## 最初に実行すること

Windowsキーを押しながらRを押し、`cmd`と入力してEnterを押します。黒い画面で次の1行を実行します。

```bat
cd /d "%USERPROFILE%\Downloads\tamaya-server-setup\tamayaapp-main" && curl.exe -fL --retry 3 "https://raw.githubusercontent.com/iichi86/tamayaapp/e81bd799185aa00585cedab95a198d0646e4ee6f/scripts/prepare-ios-build.mjs" -o "scripts\prepare-ios-build.mjs" && node scripts\prepare-ios-build.mjs --build --submit
```

このコマンドは、用意した準備スクリプトを取得して実行します。スクリプトの内部では検証済みコミットのファイルを取得し、内容のハッシュが一致してから更新します。既存の接続設定を保持し、今回承認された設定を更新して、チェックとビルドへ進みます。ビルド成功後はTestFlightへのアップロードも自動で進めます。ダウンロードや確認に失敗した場合はエラーを表示して止まります。

Appleのログイン・認証コード・アップロード用の鍵等を求められたら、ご本人が黒い画面で対応します。質問の意味が分からない場合は、その画面を送ってください。ビルドが始まった場合は、表示されたExpoのビルド画面で状況を確認します。ビルド・アップロードの結果を確認してから、iPhoneへTestFlight版を入れる操作を案内します。

この一括操作は、段階1のビルドと段階2のアップロードを対象にします。App Reviewへの審査提出と一般公開は、実機・掲載情報の準備を終えた後の段階です。`--submit`を省いた`--build`のみの指定ではビルドまで、`--local-only`ではローカルの更新・チェックまでを実行できます。

## 段階2以降に使う準備

### App Store ConnectとTestFlight

EAS CLI 25.3.0の提出処理には、必要なApp Store Connectのアプリ登録と内部TestFlightグループの準備を進める機能があります。今回の`eas.json`には掲載名「むさしの玉屋」、日本語`ja`、SKU、正式なBundle IDを設定しました。最初から同じ情報をブラウザーへ手入力する手順を標準にはしません。

最初の一括操作に`--submit`を指定すると、成功したビルドのアップロードを自動で進めます。改めて提出操作を行う必要がある場合は対象を確認します。対象が明確な場合は`--id`を指定し、今回のプロジェクトに対象の最新ビルドだけがある場合は次の操作を使えます。

```bat
npx eas-cli@25.3.0 submit --platform ios --profile production --latest --auto-testflight-setup
```

これはAppleへのアプリ本体のアップロードです。一般公開の審査提出・公開ボタンとは別の段階です。Appleから契約の確認が求められた場合や、名称が使用できない場合は、表示内容に合わせて対応します。自動作成後の掲載名が「むさしの玉屋」であることも確認します。

### 掲載文章と申告

日本語の掲載文と公開URLは[掲載準備](STORE_LISTING.md)にあります。入力を減らすための設定ファイルと同期方法は[掲載情報の同期](RELEASE_METADATA.md)にまとめます。審査の連絡先・ログイン用パスワード等は公開GitHubへ書かず、所有者のPC内とAppleの画面で扱います。

プライバシー・年齢区分・権利情報の全回答を、自動で確定したとは扱いません。実際に表示される質問と現在の実装を照合し、その段階でまとめて案内します。

### 実機確認と公開時の運用

すでにExpo Goで確認した全操作を、理由なく最初から繰り返す手順にはしません。署名付きアプリの起動・ログイン・会員情報・QR等、配布版で確認する必要がある要点に絞ります。掲載画像には実際の署名付きアプリの画面を使います。本番の残高・日付を作り替えたり、5日間待つことを作業全体の条件にしたりしません。

バックアップの担当・保存先・保管期間と、審査・一般公開中のAPIの稼働方法は、公開前に実際の運用と合わせます。現在のFreeのまま署名付きアプリの準備を進められます。新しい有料契約が必要な選択は、内容と金額が分かる段階で別に判断します。
