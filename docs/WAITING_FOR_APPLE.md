コードの準備と、所有者のRender・Windowsのファイルへ反映されたことは別の状態です。次の順で進めます。

## 1．Renderへ最新版を反映する

1. [Render](https://dashboard.render.com/)へログインします。
2. Web Serviceの`tamayaapp`を開きます。プロジェクト一覧にいる場合は、サービス名のリンクを押します。
3. 最新コミットの自動デプロイが進んでいる場合は、完了を待ちます。反映されていなければ`Manual Deploy`→`Deploy latest commit`を選びます。
4. 成功して`Live`になったことを確認します。失敗した場合は、成功扱いにせず表示されたログを確認します。
5. PCのChromeで`https://tamayaapp.onrender.com/health`を開き、`status=ok`、`authMode=firebase`を確認します。

これで新しいサーバーを実環境で確認できます。退会から90日後を待つ試験や、本番の残高・日付を変更する操作は必要ありません。

## 2．スタッフ確認用の会員で退会を確認する

対象は、別のメールアドレスで作成し、スタッフ権限を停止した**0スタンプの確認用会員**です。先にそのメールアドレス・会員証を確認します。オーナーとして日常管理に使う会員は、この確認の対象にしません。

1. 2台目で、Expo Goから玉屋の会員アプリを開きます。確認用のメールアドレスでログインしていることと、0スタンプであることを確認します。
2. 玉屋アプリの「設定」→「退会・アカウント削除」を押します。
3. 「本人確認のため現在のパスワード」に、その確認用会員のパスワードを入力します。
4. 確認欄へ`退会する`と入力します。
5. 対象の確認用会員を削除する操作で、元に戻せないことを確認し、「確認してアカウントを削除する」を押します。
6. 「退会とアカウント削除が完了しました。」と表示され、会員証のQRが表示されなくなることを確認します。
7. 完了と表示された場合は、同じ確認用メール・パスワードでのログインが拒否されることを1回確認します。オーナー側の会員は引き続き使います。

「削除の受付が完了しました。アカウントの利用を停止し、サーバーで削除を続けます。」と表示された場合は、受付と完了を区別して担当者へ伝えます。再登録を繰り返して結果を判断する手順にはしません。

## 3．PC側のビルド用ファイルを更新する

ZIPで使っているWindows側へ、ビルドに渡すファイルの整理とNodeの指定を反映できます。アプリ直下の黒い画面で次を1行ずつ実行します。

```bat
cd /d "%USERPROFILE%\Downloads\tamaya-server-setup\tamayaapp-main"
```

```bat
curl.exe -fL --retry 3 "https://raw.githubusercontent.com/iichi86/tamayaapp/84c1af5afdeadc199e0bd905d1926d4b25cb6106/.easignore" -o .easignore
```

```bat
curl.exe -fL --retry 3 "https://raw.githubusercontent.com/iichi86/tamayaapp/84c1af5afdeadc199e0bd905d1926d4b25cb6106/eas.json" -o eas.json
```

取得エラーが出た場合は、その表示を確認してから続けます。今回はビルド用の2ファイルの更新です。署名付きビルドは、Appleの有効化と正式な識別子・公開文書の確定後に行います。

## 4．掲載名・アイコンを確認する

掲載名の案は「むさしの玉屋」、現在のアイコンは[深緑と「玉」のデザイン](../assets/app-icon.png)です。[掲載文案](STORE_LISTING.md)を読み、変更希望があれば確定します。正式な店舗ロゴを使う場合は、使用できる素材を用意します。

App Store用の実機スクリーンショットは、署名付きアプリが完成した後に撮影します。今は撮影する画面と文章を準備する段階です。

## 5．バックアップの運用を選ぶ

手動取得の手順は準備済みです。自動取得を選ぶ場合、Supabase Proは基本月額25米ドルで、直近7日分の日次バックアップが含まれます。税・為替・追加利用分は公式の契約画面で確認します。毎日正常に取得できても、直近の取得から後の最大約1日分は含まれない可能性があります。

有料契約はまだ選択・実行していません。実際のお客様の会員運用を始める前に、取得担当、保存先、日次取得、復元手順を決めます。保管7日分は手動運用の提案で、採用済みの規則ではありません。

## Appleの有効化後に行うこと

Appleからの案内に沿って登録を完了し、Identifiersを利用できることを確認します。その後に正式なBundle IDと署名設定をそろえます。公開文書の正式化・運営者による確認も残っています。配布前チェックの未解決項目を残したまま、承認フラグだけを変更する手順にはしません。
