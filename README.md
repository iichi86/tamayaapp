# むさしの玉屋 会員アプリ — ローカルデモ

React Native / Expo / TypeScript で作った、iPhone で操作できる会員・来店スタンプの試作品です。お客様向けの会員証、スタンプ、クーポン、商品・店舗情報、お知らせと、スタッフ向けの読み取り・付与・クーポン使用・お知らせ編集を試せます。

実在のお客様の情報は入れず、架空のニックネームでお試しください。**デモの会員証・クーポンは実店舗では利用できません。** データはその端末に保存します。別の端末とは同期しません。お客様／スタッフの切り替えはデモ操作で、スタッフ認証ではありません。

実機での試作確認の次は、[今の試作から本番用へ改修する手順](docs/PRODUCTION.md)で、仕様の確定、保存先の準備、認証・権限・共有処理の実装、2端末での確認を進めます。Supabaseを使う場合の準備方法を具体例として記載しています。サービスの採用・契約や本番機能の実装はまだ行っていません。

App Store で一般公開する場合は、その後に[Windows から一般公開までの手順](docs/APP_STORE.md)へ進みます。付属の `eas.json` はストア向けビルド設定のひな形です。Apple 登録、EAS プロジェクトとの紐付け、アイコン、署名付きビルド、審査提出は未実施です。

## 最初に準備するもの

- このプロジェクト一式を置いた PC（Windows / macOS / Linux）と、[Node.js LTS](https://nodejs.org/)（この環境では v24.19.0 を使用）。
- iPhone と App Store 版 [Expo Go](https://apps.apple.com/jp/app/expo-go/id982107779)。
- PC と iPhone を接続する同じ Wi-Fi。開発サーバーは自分の PC で起動してください。
- [無料の Expo アカウント](https://expo.dev/signup)。PC の Expo CLI と iPhone の Expo Go に同じアカウントでログインします。

このデモの実行に API キー、外部データベース、有料サービス、Apple Developer Program の登録は不要です。App Store への公開や課金機能は含みません。

**SDK は Expo 57 を使用します。** 2026 年 10 月 25 日（日本時間）、利用者の iPhone で「インストール済みの Expo Go は SDK 57 用、プロジェクトは SDK 54」と表示されたため、プロジェクトを SDK 57 に更新しました。以前の「App Store 版 Expo Go は SDK 54 に対応する」という案内は、今回の端末には合っていませんでした。Expo Go の対応 SDK は変わるため、実際の端末の表示とプロジェクトのバージョンを照合してください。SDK 57 の最低 iOS バージョンは 16.4 です。Expo Go 自体のインストール条件は、お使いの iPhone の App Store 表示も確認してください。

公式情報：[SDK 不一致の説明](https://docs.expo.dev/troubleshooting/expo-go-version-mismatch/)、[iPhone の同一アカウント要件](https://docs.expo.dev/troubleshooting/expo-go-sign-in-required/)。SDK を更新したことと、iPhone 実機でアプリの操作を確認したことは別です。実機での起動・カメラ・表示は、[iPhone 確認チェックリスト](docs/IPHONE.md)で確認してください。

## iPhone で起動する

以前ダウンロードした SDK 54 版で不一致の画面が出た場合は、先に [Windows で SDK 54 版を更新する手順](docs/IPHONE.md#pc旧sdk-54版を更新する今回の不一致エラーが出た場合)を実行してください。ZIP 全体をダウンロード・展開し直す必要はありません。

1. PC のターミナルを開き、この README が入っているフォルダーへ移動します。Windows で、これまでの手順どおりダウンロード・展開した場合は、黒い画面（コマンドプロンプト）に次の 1 行を貼り付けて Enter を押します。保存先を変えた場合は、`package.json` が入っている場所に読み替えます。

   ```bat
   cd /d "%USERPROFILE%\Downloads\tamayaapp-main\tamayaapp-main"
   ```

2. 次を 1 行ずつ実行します。`npm ci` は必要な部品を、付属のロックファイルと同じバージョンでインストールします。

   ```sh
   npm ci
   npx expo login
   npm start -- --go --clear
   ```

3. iPhone に Expo Go をインストールし、PC と同じ Expo アカウントでログインします。
4. PC と iPhone を同じ Wi-Fi に接続します。PC に `Use port 8082 instead? (Y/n)` と表示された場合は、半角の `y` を入力して Enter を押します。起動後、**コマンドを入力した同じ黒い画面**に QR が表示されます。見えなくなった場合は、サーバーが動いている間に半角の `c` を 1 回押すと再表示できます。このとき Enter は不要です。
5. iPhone の標準「カメラ」で、黒い画面の **起動用 QR** を読み取り、Expo Go で開きます。ローカルネットワークへの接続を求められたら許可します。
6. ターミナルを開いたまま操作します。終了するときは PC で `Ctrl + C` を押します。

起動用 QR は、アプリ内の **会員証 QR** とは別物です。スタッフ画面で読み取るのは会員証 QR です。

`npm run ios` は **Mac と Xcode / iOS Simulator がある場合**のショートカットです。Windows / Linux から iPhone の Expo Go で試す場合は、上記の `npm start -- --go --clear` を使います。

### 開けないとき

- アカウントのエラー：`npx expo whoami` で PC のアカウントを確認し、Expo Go と合わせます。ログイン後は端末の「Try Again」で再試行し、別アカウントへ変更した場合は `npm start` を起動し直します。
- SDK のエラー：`Project is incompatible with this version of Expo Go` と表示された場合は、画面の「installed version」と「project」の SDK を確認します。この版は SDK 57 です。以前の SDK 54 版をダウンロードしていた場合は、PC 側のプロジェクトの更新が必要です。iPhone の Expo Go を削除したり、端末を初期化したりする必要はありません。
- 接続待ち：同じ Wi-Fi、VPN、PC のファイアウォール、iPhone のローカルネットワーク許可を確認します。公共 Wi-Fi は端末間通信を禁止していることがあります。
- LAN でつながらない場合：サーバーを止めて `npx expo start --tunnel` を試せます。追加ツールのインストール案内とインターネット接続が必要で、読み込みが遅くなることがあります。
- 更新が反映されない場合：`npx expo start --clear` で開発サーバーのキャッシュを消して再起動します。これは会員データの初期化ではありません。

## デモで試す流れ

### お客様

1. 下の「会員証」で架空のニックネームを入力し、「会員証をつくる」を押します。発行された会員番号と会員証 QR を確認します。
2. 「会員証」でスタンプ、「特典」でクーポンを確認します。来店スタンプは 1 会員につき **日本時間の同じ日には 1 個**までです。
3. 10 個たまると、残数が 0 個になり、**100 円引き・発行から 30 日間有効**のクーポンが 1 枚発行されます。
4. 利用可能なクーポンを店頭で提示し、スタッフが使用を確定します。お客様だけで使用済みにする操作はありません。

### スタッフと「あと 1 個」のデモ

1. 右上「デモ」を開き、「体験用の会員（サンプル・9スタンプ開始）」に切り替えます。初期データの「使用済み」「期限切れ」クーポンは、表示を試すための過去の見本です。
2. 「デモ」→「店舗用に切り替える」でスタッフ画面を開きます。**「デモ会員を選択する」**でその会員を指定し、「スタンプ付与の確認へ」→「確認して1スタンプ付与」で付与します。カメラを使わず、一台で流れを試せます。
3. お客様画面へ戻り、スタンプ残数 0 個と、今回発行した利用可能クーポン 1 枚を確認します。同じ日の再付与では増えません。
4. お客様の「特典」から新しい未使用クーポンを開き、「店頭で提示する」→「クーポンを提示する」で特典番号を確認します。提示を終えてスタッフ画面へ切り替え、同じ番号の「特典利用の確認へ」→「確認して使用済みにする」で使用を確定します。使用済みになると再利用できず、期限切れのクーポンも使えません。
5. スタッフ画面でサンプルのお知らせを編集し、お客様画面への反映も確認します。

実際のカメラ読み取りは、別の画面や端末に会員証 QR を表示して、スタッフ画面からカメラを開いて試します。カメラの許可が必要です。**QR を読み取っても端末間のデータ同期は起きません。** スタッフ側にも存在するサンプル会員の QR で試してください。別端末で新しく登録した会員は、スタッフ側のローカルデータには存在しません。

デモの初期化は確認画面で確定してから行います。その端末で登録・付与・使用・編集したデータが消え、サンプルデータに戻ります。アプリを通常の再読み込み・再起動した場合は保存データを引き継ぎます。

詳しい実機手順と結果記録は [iPhone 確認チェックリスト](docs/IPHONE.md) を使ってください。

## PC のブラウザーで確認する

```sh
npm run web
```

ターミナルに表示された Web のアドレスを PC のブラウザーで開きます。画面・登録・スタンプ・クーポンの流れを確認できます。ブラウザーの保存データは iPhone のデータとは別です。Web 版ではカメラを使わず、「デモ会員を選択する」で試します。カメラの許可や iOS の表示は、iPhone 実機で確認してください。

## 設定を変える

店舗情報、商品、配色、スタンプ数、割引額、有効日数は [src/config/shop.ts](src/config/shop.ts) にまとめています。

- 店名：むさしの玉屋。所在地の範囲：東京都中野区・新中野駅周辺。
- 商品：どら焼き、鍋横最中、長者もち、お赤飯。
- 未確認の正確な住所、電話番号、営業時間、商品説明、価格は `null` とし、具体的な情報を作っていません。確認後に設定してください。
- 商品ビジュアルは文字と図形によるイメージで、お知らせもデモ用です。実店舗の情報・商品画像・利用条件へ差し替えてから運用してください。

設定を変更しても、保存済みの付与履歴やクーポンの有効期限は再計算しません。割引額の表示は、既存クーポンも現在の設定値を使います。条件を変えるデモ確認では、初期化してから試してください。

## 開発用の確認コマンド

今回の結果と画面画像は [検証結果](docs/VALIDATION.md) にまとめています。ソースは `App.tsx`（画面切り替え）、`src/screens`（画面）、`src/domain`（スタンプ・特典の計算）、`src/storage`（保存）に分けています。保存先をサーバーに変える場合は `StorageAdapter` とリポジトリを境界にし、本番の付与・使用判定はサーバー側へ移してください。

```sh
npm test
npm run typecheck
npm run export:ios
npm run export:web
npm run test:browser
```

`test` はスタンプ・クーポン・保存処理の自動テスト、`typecheck` は TypeScript の検査です。`export:ios` と `export:web` は配信用コードの生成確認です。**iOS の export 成功は、実機動作や署名済み iOS アプリのビルド成功を意味しません。** `test:browser` は Playwright によるブラウザー操作の確認です。Chromium が入っていない PC では、先に `npx playwright install chromium` を実行します。

この作業環境は Linux です。iPhone 実機および iOS Simulator の起動・カメラ権限・実機表示は未確認です。実機確認欄は [docs/IPHONE.md](docs/IPHONE.md) に記録します。

## 実店舗で使う前に必要なこと

このデモは AsyncStorage に保存し、端末の時計で判定します。本番では次が必要です。

- お客様とスタッフの認証、スタッフの権限確認、退職・紛失時のアクセス停止。
- サーバー側で管理する会員・来店・クーポンと、複数端末への同期。
- 同時操作でも付与・発行・使用が一度だけ成立するデータベース処理、サーバー時刻による日付・期限判定。
- 監査ログ、障害時の復旧、バックアップと保存期間。
- 個人情報の取り扱い、プライバシーポリシー、利用規約、同意・削除の手順。
- 会員 QR のコピー・使い回し対策と、店舗での本人・来店確認。
- 割引対象、併用、最低購入額などのクーポン条件と店舗の正式な承認。

App Store 提出、署名、実運用のサーバー、決済は、このデモには接続していません。
