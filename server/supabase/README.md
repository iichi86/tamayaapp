# Supabase の保存先

Firebase Authentication はログインだけに使用し、会員・スタッフ権限・スタンプ・クーポンは PostgreSQL の非公開 `tamaya` スキーマに保存します。Expo から Supabase のテーブルへ直接アクセスしません。

`001_initial.sql` はデータベース所有者の接続で実行します。再実行で会員データを消しません。公開スキーマへの追加や `anon` / `authenticated` への権限付与は不要です。これらのロールには許可ポリシーもありません。

実行用の接続ユーザーには、管理者から `tamaya_api` ロールだけを付与してください。`tamaya_api` 自体はログイン不可・管理権限なし・RLS回避権限なしです。実行ユーザーのパスワードはホスティングの秘密設定で管理します。管理者用の接続文字列はマイグレーション時にのみ使用してください。接続文字列を `.env`、ログ、チャット、GitHub、Expo の `EXPO_PUBLIC_*` に公開しないでください。

`tamaya_api` にはサーバー処理用の全行ポリシーがあります。店舗・本人・スタッフのアクセス制御は、検証済み Firebase UID とデータベース内の権限を使う管理APIで行います。RLSだけで、サーバーの認可を置き換えてはいません。

接続はサーバーだけに `DATABASE_URL` を設定します。Supabase の共有プーラーまたは直接接続に対応した、ホスティングから到達可能な接続先を選び、TLSの証明書確認を有効にしてください。アプリには URL、匿名キー、service_role キー、DBパスワードを設定する必要がありません。

正式な特典内容が未設定の場合、`operationsEnabled: false` のまま稼働します。この場合、登録・照会はできますが、スタンプ付与とクーポン使用は停止します。以前の試作用100円引きを本番用条件として流用しません。
